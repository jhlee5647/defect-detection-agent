# SPEC.md — MVP 범위 및 개발 단위 목록

> SDD 최상위 문서. 하위: 단위별 계획(각 게이트 1에서 상세화).
> 이 문서는 "무엇을 어떤 순서로 만드는가"만 확정하고, 각 단위의 상세 설계는 착수 시점에 정한다.

## 1. 목적

신규 점검 사진을 넣으면 과거 유사 사례·설비 이력을 스스로 찾아 근거로 제시하며 결함을 진단하고 점검 리포트를 생성하는 단일 에이전트 시스템의 MVP를 구축한다.

## 2. 전제

- 전체 데이터 600GB(100,616쌍)는 로컬 불가 → **샘플 94쌍**(풍력 75 + 태양광 19, `data/`)으로 실사용자 1명 가정 기능 검증.
- 실행 환경: 이 Windows PC + Claude API. 임베딩 2종만 로컬 CPU.
- 데이터 실측 명세는 [DATA_NOTES.md](DATA_NOTES.md), 기술 선택 근거는 [adr/](adr/) 참조.

## 3. 범위

**만드는 것**
- 도구 4종 전부 (visual_search / history_query / knowledge_search / vlm_analyze)
- ReAct 루프 (6회 상한 · 독립 도구 병렬 · 중복 호출 코드 가드 · 구조화 로그)
- 리포트 6항목 + 자기검증
- UC-1/2/3 실데이터 재현, UC-4/5/6은 기능+모의
- 평가: E1(3조건 비교)·E2(클래스별)·E3(라우팅)·E4(인용 정확성) — **풍력 전용**
- Gradio 데모 (중간 추론 표시)

**만들지 않는 것**
- VLM 파인튜닝, 시계열 자동 매칭, 멀티턴 메모리, 계정/권한, 실시간 처리, 프로덕션 배포
- 태양광 평가 채점 (인덱싱·UC-6 기능 데모만)
- T3 가이드라인 문서 코퍼스 (샘플에 없음 — 캡션 94건만)

## 4. 아키텍처 요약

- **단일 에이전트**: 판단 주체는 오케스트레이터(A1) 하나. 도구 4종은 자율성 없는 함수.
- 저장소 3종: V1(Chroma 이미지) / V2(Chroma 텍스트) / D1(SQLite 이력) + S0(질의 단위 인메모리 Evidence Store).
- 오프라인 플레인(P1 인덱싱)과 온라인 플레인(질의 처리) 코드 분리. 온라인은 저장소 읽기 전용.
- 금지 상호작용: 도구 간 직접 호출, 도구의 S0 접근, 온라인 플레인의 저장소 쓰기.
- 설계 원칙 4개: 벡터스토어·LLM 인터페이스 추상화 / 설정 외부화(.env+pydantic-settings) / 플레인 분리 / 에이전트 코어와 UI 비결합.

## 5. 개발 단위 목록 (진행 순서)

평가 하네스 최우선 원칙에 따라 파서→홀드아웃→채점기를 도구 구현보다 앞에 둔다.

| # | 단위 | 완료 기준(요약) | 게이트 |
|---|---|---|---|
| U0 | 프로젝트 스캐폴딩 — pyproject, ruff, pytest, pydantic-settings, .env.example, src 레이아웃 | pytest·ruff 빈 프로젝트에서 통과 | 축소 |
| U1 | 라벨 JSON 파서 — visionqa 스키마, 설비별 카테고리 매핑, db_name 판별, 대표결함 선정 | 94쌍 전건 파싱 + DATA_NOTES 함정 케이스 테스트 통과 | 풀 |
| U2 | 홀드아웃 분할 + 유입 차단 — 풍력 결함 74장에서 클래스 층화 ~20장, V1·V2·D1 전부 물리 제외, 차단 검사 스크립트 | 분할 재현 가능(시드 고정) + 차단 검사 동작 | 풀 |

| U4 | D1 이력 DB 구축 — 파일명·JSON → SQLite 정형 레코드 | 94건 적재 + 스키마 검증 테스트 | 풀 |
| U5 | V1 이미지 인덱싱 — SigLIP 임베딩, 전체+대표결함 크롭, 홀드아웃 제외 | 인덱스 건수 검증 + 차단 검사 통과 | 풀 |

| U7 | T4 vlm_analyze — Claude vision, 크롭/few-shot/비교 모드 | 모드별 단위 테스트(모의)+실호출 스모크 | 풀 |
| U8 | T1 visual_search — 유사 사례 k건 + 라벨·심각도·캡션 반환 | 홀드아웃 이미지 질의 시 자기 자신 미반환 검증 | 풀 |

| U10 | T3 knowledge_search — 텍스트 검색 + 출처 표시 | 검색 정확성 스모크 테스트 | 풀 |

단위 진행 중 목록 자체의 수정(분할·순서 변경)이 필요하면 이 문서를 갱신하고 커밋에 남긴다.

## 6. 평가 설계 (풍력 전용)

- 홀드아웃: 풍력 결함 74장에서 클래스 층화 ~20장. V1·V2·D1 전부 물리 제외 (희소 클래스는 전량 포함 원칙과 층화를 U2 계획에서 조정).
- E1: (a) VLM 단독 / (b) VLM+유사사례 / (c) 전체 에이전트 3조건의 VQA 정답률 비교.
- E2: 클래스별 분해 보고 (샘플 규모상 건수 병기).
- E3: 테스트 질의 세트(UC 기반)에 대한 라우팅 정확도 80% 이상.
- E4: 리포트 샘플의 인용 실존·일치 검사, 허위 인용 5% 미만.
